# 카드뉴스 오토파일럿

주제 하나로 인스타그램 카드뉴스 캐러셀을 완성하고, 원하면 매일 자동으로 굴러가게 만든다.

## 두 가지 모드

| 모드 | 하는 일 | 필요한 것 |
|---|---|---|
| **생성 모드** (기본) | 주제 → 뉴스 수집 → 카피 → 카드 이미지 | 없음. 바로 실행 |
| **자동 모드** (프로) | 매일 정해진 시간에 텔레그램으로 초안 → 버튼 눌러 인스타 발행 | 텔레그램 봇, 인스타 비즈니스 계정, GitHub 계정 |

자동 모드는 사람 없이 원고를 써야 하므로 모델을 부를 수단이 하나 필요하다. **Claude 구독(Pro/Max/Team/Enterprise)이 있으면 `claude setup-token` 으로 발급한 `CLAUDE_CODE_OAUTH_TOKEN` 만으로 충분하고, API 요금이 따로 나가지 않는다.** 구독이 없을 때만 `ANTHROPIC_API_KEY` 를 쓴다.

사용자가 "카드뉴스 만들어줘"라고 하면 **생성 모드**다. "매일", "자동", "예약", "텔레그램" 같은 말이 나오면 자동 모드 세팅을 안내한다.

## 생성 모드 워크플로

### 0단계 — 최초 1회만: 의존성 설치

`node_modules` 가 없으면 스킬 폴더에서 실행한다.

```bash
npm install
```

### 1단계 — 무엇을 만들지 정한다

**기본은 "사건 하나를 깊게 파는" 스토리형이다.** 사용자가 "모아보기", "주간 정리" 를 명시하지 않는 한 이쪽으로 간다.

사용자가 다룰 사건을 이미 말했으면 그대로 쓴다. 분야만 말했으면(예: "AI 뉴스") **먼저 훑어서 오늘의 큰 건을 찾아 제안한다.** 되묻기 전에 후보를 보여주는 게 빠르다.

```bash
node scripts/fetch-news.mjs --preset tech --hours 48 --limit 30 --cluster --out out/scan.json
```

`--cluster` 는 같은 사건을 다룬 기사를 묶어 준다. **묶음이 클수록 여러 매체가 다룬 큰 사건**이다. 상위 묶음 2~3개를 사용자에게 제시하고 고르게 한다.

주제가 정해지면 다음 단계로 간다.

### 2단계 — 그 사건만 집중 수집

정해진 사건에 대한 **모든 보도**를 모은다. 여러 매체를 모아야 사진도 늘고 사실관계도 교차 확인된다.

```bash
node scripts/fetch-news.mjs --query "DeepMind WeatherNext hurricane forecast" --preset tech \
  --match "weathernext,hurricane,cyclone,deepmind" \
  --hours 168 --limit 20 --full --out out/news.json
```

**`--match` 가 핵심이다.** `--query` 는 구글 뉴스 검색에만 걸리므로, 매체 RSS 로 들어온 기사까지 주제로 좁히려면 이게 필요하다. 없으면 엉뚱한 기사가 잔뜩 섞인다.

주요 옵션:

- `--match` — 이 단어들 중 하나라도 있어야 통과 (쉼표 구분) ← **사건 하나만 모을 때 필수**
- `--preset` — 분야별 매체 RSS 묶음
- `--query` — 구글 뉴스 검색어. `OR`, `"따옴표"` 지원
- `--feeds` — 매체 RSS 직접 지정 (쉼표 구분)
- `--full` — 기사 **본문 전문과 사진 여러 장** 추출 ← 필수
- `--cluster` — 같은 사건끼리 묶어 보여주기
- `--hours` `--exclude` `--limit` `--prefer-images`

프리셋: `tech` `tech-kr` `business` `world` `science` `crypto` `design` `health` `kr`
(`config/presets.json` 에서 확인·수정)

수집 후 확인할 것:

- **`fullText` 가 있는 기사가 하나도 없으면** 카드를 못 만든다. 매체 RSS(`--preset`/`--feeds`)를 넣었는지 확인한다. 구글 뉴스 링크만으로는 본문도 사진도 안 나온다
- **사진이 0장이면** 사용자에게 알린다. 글만으로도 만들 수는 있지만 품질이 떨어진다고 말해준다
- 여러 기사의 `fullText` 를 **모두 읽고** 사실관계를 맞춘다. 한 기사만 보고 쓰지 않는다

### 3단계 — 카피 작성 ← **여기가 품질을 좌우한다**

`references/copywriting.md` 를 **반드시 먼저 읽고** 그 규칙대로 쓴다. 글자 수 제한을 어기면 렌더링이 깨진다.

수집한 기사를 **전부 읽고** 하나의 이야기로 재구성해 `out/draft.json` 에 쓴다.

```json
{
  "title": "AI가 태풍 예보를\n하루 앞당겼다",
  "subtitle": "기상학자들도 놀란 딥마인드의 결과",
  "coverImage": "https://... (news.json 의 image 값을 그대로 복사)",
  "cards": [
    {
      "headline": "네이처에 실렸다\n예보가 하루 빨라졌다",
      "body": "첫 문장.\n**강조할 사실**이 담긴 둘째 문장.\n셋째 문장.",
      "source": "Ars Technica · Nature",
      "image": ""
    }
  ],
  "caption": "인스타그램 캡션 본문",
  "hashtags": ["#AI", "#딥마인드"],
  "sources": [{ "title": "기사 제목", "link": "https://...", "publisher": "매체명" }]
}
```

구성 원칙은 `references/copywriting.md` 의 "스토리형 구성" 을 따른다. 요약하면:

- **본문 카드 4~6장, 카드마다 논점 하나.** 무슨 일이 → 왜 중요한가 → 배경 → 사례 → 남은 질문
- `body` 는 **2~4문장, 문장마다 `\n`, 한 문장 30자 이내.** 숫자·인용은 `**강조**`
- `image` 는 `news.json` 의 값을 **그대로 복사**한다. **절대 URL 을 지어내지 않는다**
- 사진이 없는 카드는 `"image": ""` 로 둔다. 글만 있는 카드로 예쁘게 나온다
- **같은 사진을 두 곳에 쓰지 않는다** (표지 포함)
- 표지+본문+엔딩 합쳐 **최대 10장** (인스타 캐러셀 한도)
- **원문에 없는 숫자·발언·날짜를 만들어내지 않는다.** 불확실하면 그 카드를 뺀다

### 4단계 — 템플릿 선택

기본값은 **`story`** — 사진 + 헤드라인 + 설명이 함께 나오는, 사건 하나를 풀어내는 형식이다. 특별한 이유가 없으면 이걸 쓴다.

| 상황 | 템플릿 |
|---|---|
| 사건 하나를 깊게 (기본) | `story` |
| 여러 뉴스 모아보기 | `news` |
| 사진 없이 타이포로 | `minimal` `breaking` `magazine` `darktech` `board` |

`references/templates.md` 에 각각의 설명이 있다. 사용자가 지정하지 않으면 **골라주고 이유를 한 줄로 말한다.**

### 5단계 — 이미지 생성

```bash
node scripts/render.mjs --draft out/draft.json --template story --out out/cards \
  --handle "@my_news" --label "최신 AI 뉴스"
```

`--label` 은 카드 상단 키커의 뒷부분이다(`my_news | 최신 AI 뉴스`). 강조색은 `--accent "#3B82F6"`.

사진은 렌더 시 자동으로 내려받아 카드에 합성된다. `out/cards/01.jpg` … 형태로 1080×1350 JPEG 이 나온다.

### 6단계 — 결과 전달

1. 생성된 이미지를 **읽어서 직접 확인한다.** 사용자에게 깨진 결과를 그대로 주지 않는다. 특히:
   - 글자가 넘치거나 잘렸는가 → 카피를 줄여 3단계부터 다시
   - 사진이 안 붙은 카드가 있는가 → 렌더 로그의 `이미지 N/M장 확보` 를 확인. 실패했다면 다른 기사로 교체
   - 사진이 헤드라인과 맞는가 → 엉뚱한 사진이면 그 카드를 바꾼다
2. 이미지 파일들을 사용자에게 보여준다.
3. 캡션 + 해시태그를 **복사하기 쉽게 하나의 코드블록으로** 출력한다.
4. 자동 모드를 아직 안 썼으면 "매일 자동으로 받아보시겠어요?" 한 줄로 안내한다. 강요하지 않는다.

## 리드 마그넷 (자료집 PDF)

카드뉴스에 "댓글 남기시면 자료집 보내드려요" 를 붙이려면 **줄 물건**이 있어야 한다. 바이럴이 도는 계정들의 실제 동력은 카드 디자인이 아니라 이 자료집이다.

사용자가 "자료집 만들어줘", "무료 배포용 PDF", "리드 마그넷" 같은 말을 하면 이걸 쓴다.

```bash
node scripts/leadmagnet.mjs --topic "이번 주 AI 뉴스 총정리" --preset tech --days 7
```

`out/magnet/leadmagnet.pdf` 가 나온다. 원고는 `out/magnet/report.json` 에 남으므로, 문구만 손봐서 다시 구울 때는 `--report out/magnet/report.json` 으로 수집·작성을 건너뛴다.

**반드시 지킬 것 — 없는 사실을 만들지 않는다.** 이 스크립트는 실제로 수집한 기사만 근거로 삼는다. 사용자가 "수익 사례 100건 모아줘" 처럼 근거 없는 자료를 요구하면, 모델의 기억으로 채우지 말고 **근거가 될 자료를 어디서 가져올지 먼저 정하자고 되묻는다.** 검증 안 된 숫자가 든 자료집은 계정 신뢰를 한 번에 무너뜨린다.

항목마다 붙는 A/B/C 등급은 내용의 중요도가 아니라 **근거가 얼마나 단단한지**를 뜻한다. 면책 문구는 코드가 자동으로 붙이므로 지우지 않는다.

> 댓글 → 자동 DM 은 이 스킬 밖이다. 인스타 메시지 API 는 상시 웹훅 서버와 Meta 앱 심사를 요구한다. ManyChat 같은 도구를 쓰는 편이 빠르고, 이 스킬은 **보낼 물건**을 만드는 쪽을 맡는다.

## 자동 모드 세팅

사용자가 자동화를 원하면 `references/setup-automation.md` 를 읽고 그 순서대로 안내한다. 요약하면:

1. **텔레그램 봇 생성** → 토큰, 채팅 ID 확보
2. **인스타그램 비즈니스 계정 + Meta 앱** → 액세스 토큰, IG 유저 ID 확보
3. **GitHub 공개 레포 생성** → 이미지 호스팅 + 스케줄러를 동시에 해결
4. **세팅은 사용자에게 떠넘기지 말고 네가 실행한다.**

   `setup.mjs` 는 터미널 질문 대신 플래그로도 받는다. 사용자에게 열세 번 답하게 하지 말고, 대화로 값을 모아 한 번에 넘겨라. 필요한 건 사실상 레포와 계정 핸들 둘뿐이고 나머지는 기본값이 좋다.

   ```bash
   node scripts/setup.mjs --repo owner/repo --handle @my_account \
     --brand-label "최신 AI 뉴스" --times "08:00,19:00"
   ```

   - `--repo` 만 필수다. 레포 안에서 돌리면 `git origin` 에서 알아서 찾으므로 그것도 생략된다.
   - 분야는 `--preset`(목록은 `config/presets.json`), 직접 키워드는 `--query "..."`.
   - 전체 플래그는 `node scripts/setup.mjs --help` 로 확인한다.
   - 사람이 직접 답하고 싶어 하면 플래그 없이 `node scripts/setup.mjs` 를 터미널에서 돌리게 한다.

5. 워크플로 파일 생성 후 레포에 푸시, GitHub Secrets 등록

   `setup.mjs` 는 **레포 루트의** `.github/workflows/` 에 파일을 만든다(`.git` 을 찾아 올라간다). 출력에 찍힌 실제 경로를 사용자에게 그대로 보여주고, 그 파일과 `config/config.json`, 스킬 폴더 전체를 커밋해야 한다고 알린다 — 워크플로가 체크아웃해서 실행하기 때문이다.

세팅 중 사용자가 막히면 `references/troubleshooting.md` 를 확인한다. **토큰이나 API 키를 대신 발급받으려 하지 말고**, 사용자가 직접 발급하도록 화면 순서를 알려준 뒤 값만 받는다.

동작 흐름:

```
① 설정한 시각마다 (config.json 의 publishTimes — 개수가 곧 하루 편수)
    뉴스 수집 → 카피 → 카드 렌더 → 레포에 이미지 커밋
    → 텔레그램으로 미리보기 + [발행] 버튼
    → 초안을 대기 목록에 등록 → 처음 30분은 직접 대기

② 15분마다 (회수 잡)
    대기 중인 초안의 버튼 응답을 확인 → 눌렸으면 인스타 발행
```

**버튼은 계속 살아 있다.** 초안 잡이 끝난 뒤에 눌러도 회수 잡이 올려준다(24시간 후 만료). 같은 사건을 두 번 만들지 않도록 다룬 뉴스는 기록해 둔다.

## 중요한 규칙

- **이미지를 확인하지 않고 완료 보고하지 않는다.** 렌더 후 반드시 읽어본다.
- **없는 사실을 지어내지 않는다.** 카드뉴스는 그대로 공개 발행되므로 오보의 책임이 사용자에게 간다.
- **인스타 발행은 사용자 승인 없이 실행하지 않는다.** 생성 모드에서 `publish-ig.mjs` 를 임의로 부르지 않는다.
- **토큰/시크릿을 파일에 커밋하지 않는다.** `config/config.json` 에는 비밀값이 들어가지 않는다. 전부 환경변수·GitHub Secrets 로 간다.
- 기사 본문을 길게 그대로 옮기지 않는다. 요약하고 출처를 밝힌다.

```
scripts/setup.mjs         자동 모드 세팅 (--help 로 플래그 확인, 대화형도 됨)
scripts/leadmagnet.mjs    리드 마그넷 자료집 PDF 생성
scripts/telegram-setup.mjs 텔레그램 연결 (채팅 ID 자동 탐지)
scripts/doctor.mjs        진단 — 세팅이 막히면 제일 먼저 실행
scripts/tick.mjs          스케줄 진입점 — 초안 생성·전송
scripts/drain.mjs         늦게 누른 발행 버튼 회수
scripts/lib/state.mjs     대기 초안·다룬 사건 기록 (레포에 커밋)
scripts/telegram.mjs      텔레그램 전송 / 버튼 응답 대기
scripts/publish-ig.mjs    인스타그램 캐러셀 발행
scripts/upload-github.mjs 이미지를 공개 레포에 올려 raw URL 확보
templates/*.html          카드 디자인 6종 (CSS 직접 수정 가능)
references/               카피 규칙, 템플릿 가이드, 세팅, 문제해결
```
